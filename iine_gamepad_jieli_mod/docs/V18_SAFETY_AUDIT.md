# v18 候选固件安全审计

对象: `outputs/IINE_Kindle_Click_v18_PnP.ufw`
SHA-256: `AA6E8986E174203B51D8192B28B86B1E053214CCFA07BEB771EC1317D70549B0`

## 1. 结论

- **砖机风险: 低**。相对 v1.7 只改了 5 处常量/NOP 和 CRC 字段，Bootloader/配置/引导区完全未动。
- **可刷入性: 高**。结构与 v1.7 相同，所有 CRC 复算一致；v1.7 已在本机成功刷入并连接。
- **功能有效性: 不确定**。PnP 构造是否走到写入分支取决于运行时配置 `h[0x2D12]`，静态无法完全确定。

## 2. 与 v1.7 的差异（逐字节）

只有以下区域不同:
| 文件偏移 | 含义 |
|---|---|
| 0x0000-0x0003 | UFW 主头 CRC / 列表 CRC |
| 0x0044-0x0045 | UFW 条目 0 数据 CRC |
| 0x2400-0x2403 | JLFS app_area_head 数据 CRC |
| 0x2420-0x2423 | JLFS app.bin 条目头 CRC |
| 0x668A-0x668B | PnP VID 立即数 (0x045E→0x0171) |
| 0x6696-0x6697 | PnP PID 立即数 (0x02FD→0x0443) |
| 0x669C-0x669D | PnP PID 立即数 (0x0B13→0x0443) |
| 0x66A2-0x66A3 | PnP PID 立即数 (0x028E→0x0443) |
| 0x66A8-0x66A9 | `r0 += 0x5C` → NOP |

除此之外与 v1.7 完全一致。

## 3. 关键区域未改动（与原厂逐字节相同）

- Flash Header (0x400-0x41F)
- Boot vector (0x420-0x4A0)
- `uboot.boot` (0x4A0-0x137F, 4831B)
- `isd_config.ini` (0x177F-0x17F9)
- 对齐 gap
- `cfg_tool.bin` (0x32DC8-0x3309A)
- `p11_code.bin` (0x3309A-0x3409A)
- 尾部 0xFF padding

## 4. 校验层（全部通过）

- flash 镜像 CRC16 = 0x4A29，与 UFW 条目 0 +0x04 一致
- UFW 条目列表 CRC16 = 0x800A
- UFW 主头 CRC16 = 0x420D
- JLFS: app.bin 数据 CRC / app.bin 条目头 CRC / app_area_head 数据与头 CRC 全部一致

## 5. 补丁语义

应用 **app.bin 偏移 0x4168 起** 的 PnP 构造函数（VMA 0x1E04272）反汇编:
```
r4 = 0x0171 ; h[r2] = r4        // Amazon VID
r0 = 0x0443 ; ... ; h[r3] = r0  // Amazon PID (三条路径都改为 0x0443)
nop                             // 原 r0 += 0x5C
```
- 指令边界合法，仅为立即数替换与一条 2 字节 NOP。
- 无新增内存访问、无控制流改变 → 不会因该补丁产生非法访问/死循环。
- 前置早退条件: `(r1&0x0C)!=0`、bit7=0、`(r1&0x2070)==0`（r1 = `h[0x2D12]`）。

## 6. 已知副作用

- 该构造函数有第二个调用点 `0x1E0DEAE`（USB 描述符路径）。补丁会把 USB 模式的 VID/PID 也改为 Amazon。
- 升级工具匹配的是升级模式设备（VID 0x4C4A/PID 0x3442），不依赖该函数，因此**不影响刷机**。

## 7. 刷写前零风险验证（强烈建议）

当前手柄已运行 v1.7。先用手机上的 BLE 调试 App（nRF Connect / LightBlue）连接它，
读取 DIS 服务 `0x180A` 的 **PnP ID `0x2A50`**：

- 若读到 `0x045E / 0x0B13`（Microsoft/Xbox）→ 确认 PnP 门限是按键失效原因，v18 的方向正确。
- 若读到 `0x0171 / 0x0443` → PnP 已正确，问题在 HID 报告路径，**不要刷 v18**，应改为检查
  Report ID / usage 与 `input_manager` 日志。
- 同时确认手柄侧边开关处于 **H 档**（键盘模式）。

## 8. 如果决定刷写

1. 确认原厂 `.ufw` 与官方 `1.4.40` 升级程序可用，且原厂包 SHA-256 已核对。
2. 刷 v18（勾选“擦除整个FLASH + 成功后复位”）。
3. 刷后先看能否开机/被扫描到；若不能，先按“配对+B”2 秒进升级模式回刷原厂。
4. 若软件组合无效，按逆向报告用镊子短接 SPI NOR 的 CS 到 GND 约 0.5 秒进入 Mask ROM
   （该路径未在本机实测，属于最后手段）。

## 9. 审计结论

从“是否会把设备刷坏”的角度：v18 与已成功运行的 v1.7 只差一个只读属性构造函数里的
5 个常量字节 + CRC，Bootloader 与引导链完全未动，**风险很低**。
真正的不确定性是“补丁是否生效”，建议先做 §7 的零风险 BLE 读取，再决定是否刷写。
