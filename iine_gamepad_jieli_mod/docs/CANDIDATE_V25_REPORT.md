# 候选固件 v25 技术报告：A+B 组合键熄屏后输入屏蔽与防误触锁存架构 (终极修复版)

## 1. 背景与问题描述

在 v23 / v24 固件实测中，A+B 组合键发出 Consumer Power（`0x0030`）休眠指令功能已验证成功。但用户在日常实机使用中反馈了体验问题：
> **“A+B同时按下发出熄屏指令后，最好能屏蔽输入一段时间，kindle熄屏要几秒钟避免两个按键抬起时间不一致造成的误操作”**

### 核心物理矛盾

1. **人体手指抬起微观异步 (Asynchronous Key Release)**：
   - 当用户同时按压 A 和 B 键触发熄屏后准备松手时，人类左右手指或同一手指的微动行程存在 50ms ~ 150ms 的抬起时间差。
   - 若手指先抬起 A 键，B 键仍然压在按键行程内；微控器会将其识别为合法的“单按 B 键”，向 Kindle 发送 `PageDown`（下一页）事件。
   - 反之，若先抬起 B 键，A 键短暂停留，微控器会发送 `PageUp`（上一页）事件。

2. **Kindle 墨水屏睡眠过渡期敏感性 (E-ink Sleep Transition)**：
   - Kindle 收到 `KEY_POWER`（Consumer `0x0030`）后，`powerd` 调度电子墨水屏控制器进行波形刷新与画面冻结（过渡至屏保或关机壁纸）。
   - 在这几秒钟的过渡期内，如果蓝牙协议栈接收到任何新的按键事件，Kindle 极易被立刻打断睡眠，或在熄屏瞬间意外翻页，甚至被再次唤醒。

## 2. 两次故障深入诊断与根因剖析

### 故障一：初版 v25 断联事故 (连接成功后很快就断联)
- **根因**：误将 Flash `0x2E100` 视为代码空洞写入 90 字节代码。
- **事实**：芯片复位入口 `_start`（`0x1E0016C`）包含开机数据搬运指令 `memcpy(0x0840, 0x1E2DFC8, 3168)`。`0x2DEA8` 至 `0x308A8` 是系统 RAM `.data` 段的 Flash 加载映像！`0x2E100` 在开机时被拷贝至 **RAM `0x0A98`**，正好覆盖了 **BLE 蓝牙协议栈的底层连接状态与 GATT 上下文**，导致链路握手后迅速断联崩溃。
- **对策**：代码严格退回 `.text` 段（`0x2260A`），RAM 加载段 100% 保持原厂一致。

### 故障二：第二版 v25 A/B 键全部失效事故 ("A，B键全部失效，包括单独按和组合按……")
- **根因**：第二版试图使用 `0x2ADC` 硬件毫秒计时器，并将截止时间戳保存在 RAM `0x2B94`。
- **事实**：深入逆向 JieLi AC6321A / BD19 的 RTOS 内核：
  - `0x29B0` 是系统主任务的 Task Control Block (TCB) 基地址（在内核调度器多处 `r14 = 0x29B0`）。
  - 内核上下文切换代码 `1e2ecda: [r0 + 484] = r3`（`r0 = 0x29B0`），偏移 `0x29B0 + 484 = 0x2B94`！
  - **`0x2B94` 是 RTOS 内核正在运行任务的 `current_task_tcb` 堆栈/TCB 指针！**
  - 该指针指向 RAM 动态任务栈区（通常为 `0x4xxx` 或 `0x2xxx`），**其值绝不为 0**！
  - 当按键扫描例程执行 `r6 = [0x2B94]` 时，读取到的不是 deadline，而是任务 TCB 指针（约 15000+）；
  - `r1 = now - r6` 永远深度为负；
  - `ifs (r1 < 0) goto suppress: r0 = 0` 在**每一次按键扫描中都被无条件命中执行**！
  - 导致只要触碰 A、B 或 A+B，输入掩码 `r0` 被永久强制置零，A、B 键完全报废！

## 3. 终极架构方案：零 RAM 写入的原生按键状态锁存 (`CHORD_LATCH`)

由于微控器 RAM（`0x0840..0x40B8`）已被 BLE 协议栈和 RTOS 调度器紧密覆盖，**严禁向任何未经原厂声明的 RAM 地址写入数据**。

我们通过深入反汇编原厂固件按键处理引擎（`0x1E0E688` 与 `0x1E0E896`），发现了原厂按键状态机的天然机制：
1. **原厂按键状态变量 `[0x2B40]` (`[r14 + 400]`)**：
   - 原厂固件在 `0x1E0E896` 执行 `sw r0, [r14 + 400]`，将每一轮扫描的聚合按键码保存在 `0x2B40`。
   - 在下一轮扫描开始时，在 `0x1E0E688` 执行 `lw r1, [r14 + 400]`，若当前按键与上一次相同（`r0 == r1`），则不发出任何新的 HID 键值报文！
2. **利用 `[0x2B40]` 实现零开销防异步抬手锁存**：
   - 当 A+B 同时按下时：输出虚拟按键 2（Consumer Power，`r0 = 4`），原厂固件将其写入 `[0x2B40] = 4` 并向主机发送电源熄屏指令。
   - 当双手异步抬起时（例如 A 先抬起，B 仍压下 `r0 & 3 == 2`）：
     - 例程读取原厂 `prev_key`：`r3 = [0x2B40]`。
     - 若 `prev_key == 4` 且按键未完全释放（`r0 & 3 != 0`），例程**持续保持 `r0 = 4`**！
     - 原厂固件判定 `current_key (4) == prev_key (4)`，**绝不发出下一页（PageDown）或上一页（PageUp）！** 异步抬手残存脉冲被静默吞掉。
   - 当两根手指均完全松开行程（`r0 & 3 == 0`）：
     - 例程放行 `r0 = 0`，向主机发送正常的按键释放（Key Release）报文，原厂固件自动将 `[0x2B40]` 清零。
   - **单键（A/B/方向键）完全不受影响**：单键按下时 `prev_key != 4`，条件直接旁路，**0ms 硬件零延迟即时响应**！

### 核心优势
- **零 RAM 写入**：只读 `[0x2B40]`，绝不写入任何 RAM，从根源上杜绝与 RTOS 调度器或 BLE 协议栈的冲突。
- **超紧凑极致体积**：机器码仅 **38 字节**（远小于槽位上限 70 字节，剩余 32 字节余量）。
- **零硬件定时器依赖**：不依赖任何系统 tick，即使系统时钟波动或进入浅睡眠，按键状态机依然 100% 准确。

## 4. 汇编实现代码 (38 字节 @0x2260A)

```assembly
	.text
	.globl chord_latch
chord_latch:
	[--sp] = {rets, r13-r4}         ; 保护寄存器 (与 0x1E0C820 退出时弹出配对)
	r4 = r1                         ; 保存报文缓冲指针供后续使用
	r2 = r0 & 3                     ; 提取 A (bit 0) 与 B (bit 1) 按键
	if (r2 == 3) goto set_chord     ; 若 A+B 同时按下，直接进入组合键分支
	r3 = 0x2B40                     ; 原厂 prev_key 状态变量地址 ([r14 + 400])
	r3 = [r3 + 0]                   ; 读取上一次按键值
	if (r3 != 4) goto body          ; 若上次并非 Power 键，正常放行单键 (0ms 延迟)
	if (r2 == 0) goto body          ; 若双键均已完全松开，放行 release 报文 (r0 = 0)
set_chord:
	r0 = 4                          ; 虚拟按键 2 (Consumer Power 0x0030)
body:
	r11 = r0                        ; r11 = 处理后的输入按键掩码
	r1 = 0                          ; 满足 0x1E0C820 入口约定
	r3 = 0x1E0C820
	goto r3                         ; 返回原厂按键表聚合引擎
```

### 机器码逐字节对应 (38 字节)
```hex
7d 01 14 08 22 fd 03 09 32 e0 06 00 03 fb 40 2b 03 46 43 e0 02 10 01 24 40 70 0b 08 01 70 c3 ff 20 c8 e0 01 93 00
```
