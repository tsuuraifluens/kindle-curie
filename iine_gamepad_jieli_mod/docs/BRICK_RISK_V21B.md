# v21b 变砖风险评估

日期: 2026-10-19
候选: `release/IINE_Kindle_Click_v21b_Composite.ufw`
SHA-256: `29FDADE0BE86BA0AFD27569970D70620EBCBD8A7CE9DB54E920EEDBF9945729C`

## 结论

**v21b 可以进入“人工刷写评估”，变砖风险低；但仍禁止自动刷写。**

关键理由:
- 只修改 app.bin 内的键表、描述符选择器、Consumer 写入偏移和
  新增描述符；没有修改启动区、uboot、isd_config、cfg_tool、p11、
  flash 参数或设备唯一数据。
- UFW/JLFS 全部 CRC 已复算通过。
- 新描述符位于 app.bin 内部 `0x23330`，被 app.bin 数据 CRC 覆盖；
  该处原厂为 135 字节全 0 对齐空隙，未发现代码引用。
- v20 已被官方工具识别并刷入；v21b 与 v20 的差异全部位于
  app.bin 内部和对应 CRC，文件级结构应与 v20 同类。

“低风险”不等于“零风险”。唯一设备上仍必须保留工作区外原厂
UFW 备份，并按人工步骤刷写。

## 已核对的安全边界

### 1. 启动与配置区
`tools/audit_v21b.js` 对比原厂与候选的解密后 app 区:
- 启动头、uboot、isd_config、cfg_tool、p11 均未变化
- app 区外原始字节完全一致
- app 区尾部仍为 0xFF

即使 app 启动失败，uboot/升级模式仍在，理论上仍可重新进入升级
模式并刷回原厂 UFW。

### 2. app.bin 数据 CRC
新描述符 `0x23330..0x23386` 位于 app.bin `[0x120, 0x309C8)` 内，
因此被 app.bin 数据 CRC (JLFS `0x2022`) 覆盖。该 CRC 已重算。

### 3. 描述符落点
- 原厂 `0x23330..0x23386` 为全 0。
- 所在空隙 `0x23329..0x233AF` 长 135 字节，描述符 87 字节。
- 未发现对 VMA `0x1E23450` 的代码引用。
- 描述符结束于 `0x23386`，未覆盖 `0x233B0` 起的字符表。

### 4. 指令边界
- `0xABBE`: `50 74` -> `70 75`，2 字节长度立即数。
- `0xABC2`: 6 字节指针立即数，改为 `0x1E23450`。
- `0xC7C6`: `e8 58` -> `38 59`，2 字节半字存储，偏移 +28 -> +38。

三处都是同长度原地替换，没有改变分支/调用指令边界，也没有改变
控制流。

### 5. 内存访问
Consumer 分支写入聚合缓冲 `+38/+39`。聚合缓冲为 48 字节，
`+38/+39` 是键盘 key slot 5/6，仍在缓冲区内，不存在越界。

### 6. 描述符结构
审计内置 HID 解析:
- Report ID = 2
- Input = 64 bits = 8 字节
- Output = 8 bits = 1 字节
- 包含 Consumer Usage Page (0x0C)

键盘报告构造器未改，仍发送 9 字节包 (Report ID + 8 字节)，
与描述符长度一致。

### 7. UFW 容器
- 645,184 B
- 8 个条目，芯片名 `AC632N`
- UFW 主头 CRC、条目列表 CRC、条目 0 flash CRC 全部一致
- JLFS 四层 CRC 全部一致

## 与 v20 的差异
v20 已被工具接受并实机刷入。v21b 相对 v20 只增加:
- 键盘描述符长度/指针
- Consumer 写入偏移
- 87 字节描述符
- 对应 app.bin/JLFS/UFW CRC

没有新增 app 区外改动。这一点是 v21b 相比被拒绝的 v21 的关键修正。

## 仍然存在的风险

| 风险 | 可能性 | 影响 | 处置 |
|---|---|---|---|
| 官方工具仍拒绝 v21b | 低-中 | 不写入，不变砖 | 停止，提供具体报错，不盲刷 |
| 新描述符导致 HID 初始化异常 | 低 | 蓝牙/按键异常，可能无法连接 | 回退原厂或 v19/v20 |
| Report Map 增加 18 字节超过协议栈/主机上限 | 低 | 配对或 HID 读取失败 | 软故障，可回退；抓包确认 |
| 描述符落点被运行时使用 | 很低 | 不可预期行为 | 已确认无引用；刷后观察 |
| 整片擦除后设备唯一数据未恢复 | 很低 | 蓝牙地址/配对异常 | v18/v19/v20 已证明可恢复 |
| 原厂备份损坏 | 很低 | 无法恢复 | 刷前再次核对 SHA-256 |
| 刷写中断电/拔线/USB 接触不良 | 低 | 可能停在半擦除状态 | 用可靠数据线/直连 USB，过程中不动 |

## 刷写前必须确认
- [ ] 工作区外原厂 UFW 存在且 SHA-256 为
      `73005E7C885AAB2A644ADFDF2DBADC01802B34427E9E6FEBF823F50D4D7745E9`
- [ ] 官方升级工具版本 `1.4.40`
- [ ] 设备能进入升级模式 `VID_4C4A&PID_3442`
- [ ] 不在升级过程中断电/拔线
- [ ] 失败立即停止，不反复烧录

## 建议
先确认 v21b 能被升级工具识别（只选择文件、不点击升级）。
如果工具仍提示无法识别，立即停止，把报错原文发回；不要尝试
其他未确认文件。
