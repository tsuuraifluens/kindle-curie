## 关键根因

### 1. PnP VID/PID
v18 只改构造函数常量，构造路径有前置早退；v19 在 PnP 读取分支
无条件写入 `0x0171/0x0443`，Kindle 才开始接受按键。

### 2. 亮度必须走 Consumer 页
Linux `hid-input` 只把 Consumer `0x006F/0x0070` 映射为
`KEY_BRIGHTNESSUP/DOWN`；键盘页同名 usage 无效。

### 3. 独立 Consumer Report ID 5 不够
v20 能连接但亮度无效。Kindle 需要 Consumer usage 与键盘 usage
在同一个 application collection / Report ID 中；v21b 的 87B
复合键盘+Consumer 描述符实机全功能正常。

### 4. v22/v22s 早期的描述符指针错误
描述符实际在 app.bin `0x23330` → VMA `0x1E23450`。
v22/v22s 早期错误地把选择器指针写成 `0x1E31A60`，Report Map
指向无效区域，导致连接正常但所有按键失效。

修正后的 v22s 只改键表，已实机确认键位正常。

### 5. v23 的 A+B
在 v22s 基础上加 trampoline：
- `0x1E0C818` 入口 8 字节间接跳转到旧键盘描述符槽位
- `(mask & 3) == 3` 时把 mask 换成虚拟键 2
- 虚拟键 2 = Consumer Power `0x0030`

待实机确认触发、松开和重复发送行为。

## 已确认的硬件/协议限制

- 原厂只有配对键能点按开机；A/B/方向键不是软关机唤醒源。
- Kindle 只能被遥控器睡眠，不能被遥控器唤醒。
- 任意键开机需要改电源/唤醒层或硬件改线，当前未实现。

## 未验证项

- v23 的 A+B 触发窗口与松开行为。
- A+B 是否会重复发送 Power。
- 长时间待机、低电量、Kindle 重启后的重连。
- 电池电量服务与低电量提示（原厂是否完整保留）。
