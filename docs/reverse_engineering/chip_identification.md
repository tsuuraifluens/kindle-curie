## 2. 内存映射与存储布局 (Memory & Flash Layout)

主控芯片采用典型的哈佛/统一编址结合架构，通过内部 SPI Flash 控制器 (SFC) 与高速缓存 (I-Cache) 将外部/封装内 Flash 映射到连续的虚拟寻址空间：

```text
+-------------------------------------------------------------------+
| 0x00000000 ~ 0x00012400 : 内部 SRAM (约 73KB，存放数据、堆栈与堆) |
+-------------------------------------------------------------------+
| 0x01E00000 ~ 0x01E80000 : SPI Flash 缓存执行空间 (Code/ROData)    |
|   ├── 0x01E00000: JLFS 根目录头与引导参数                         |
|   ├── 0x01E000A0: uboot.boot (二级引导程序 SPL)                   |
|   ├── 0x01E0137F: isd_config.ini (系统配置文件)                  |
|   ├── 0x01E02000: app_dir_head (应用程序分区头)                  |
|   ├── 0x01E02120: app.bin 应用程序代码 (入口点: 0x01E00120)       |
|   ├── 0x01E329C8: cfg_tool.bin (722 字节配置工具参数块)          |
|   └── 0x01E32C9A: p11_code.bin (4KB P11 低功耗微内核)            |
+-------------------------------------------------------------------+
| 0x01E34000 ~ 0x01E7B000 : VM 分区 (约 284KB 虚拟内存/NVS 参数存储)|
+-------------------------------------------------------------------+
| 0x01E7B000 ~ 0x01E7C000 : BTIF 分区 (4KB 蓝牙链路与连接信息区)     |
+-------------------------------------------------------------------+
| 0x01E7F000 ~ 0x01E80000 : key_mac 分区 (4KB 物理蓝牙 MAC 地址区)   |
+-------------------------------------------------------------------+
| 0x02100000 ~ 0x02180000 : 内部 Mask ROM (固化杰理官方基础协议栈)  |
|   └── 包含 Bluetooth Controller 底层、Baseband、libc 与 RTOS 核心  |
+-------------------------------------------------------------------+
```

## 3. 软件架构与操作系统特征 (Software Architecture & OS)

1. **操作系统内核**:
   - 采用杰理定制的嵌入式实时任务调度器（精简版 FreeRTOS 或杰理 OS-Task 机制）。
   - 包含主事件调度循环、按键中断服务例程、蓝牙事件队列及电池低电量监控定时器。
2. **蓝牙协议栈来源与版本**:
   - 固件固化杰理官方双模蓝牙协议栈（支持 Bluetooth 5.0 BLE 与 EDR 经典蓝牙）。
   - 协议栈构建版本印记（`app.bin` 偏移 `0x235E0` 处直接检出）：
     ```text
     BTCTRLER-@20241105-$2db2c60
     ```
     证实该协议栈构建于 **2024 年 11 月 5 日**，属于非常新的杰理官方 Controller 发行版本。
3. **源码工程模块树 (从二进制内嵌断言日志反推)**:
   - `../../../../apps/hid/board/bd19/board_ac632n_demo.c`: 板级支持与 GPIO 初始化
   - `../../../../apps/hid/modules/bt/ble_hogp.c`: BLE HOGP (HID over GATT) 服务实现
   - `../../../../apps/hid/modules/bt/ble_multi.c`: 多设备/多模式蓝牙切换管理器
   - 编译工具链：杰理专有 Clang/LLVM `q32s-elf-gcc` 工具链。

## 4. 安全启动与固件保护机制评估 (Security Assessment)

| 安全机制 | 是否存在 | 判定依据与分析 | 对修改可行性的影响 |
|:---|:---|:---|:---|
| **固件加密 (Encryption)** | **是 (轻量级流密码)** | 固件采用 `jl_sfc_cipher` 流密码混淆；密钥固定为 `0x190D` 且明文存放在 `isd_config.ini` 内。 | **无阻碍**：加密算法已完全逆向并在 Python 中对称实现，可无缝重新加密。 |
| **完整性校验 (Integrity Check)** | **是 (CRC16)** | 全包使用 `jl_crc16` (CCITT-FALSE) 对容器、分块及数据进行校验。 | **无阻碍**：CRC16 可通过纯数学方法重新计算并修补，无密钥依赖。 |
| **数字签名 (Digital Signature)** | **否** | 镜像中无 RSA、ECC 或 Ed25519 签名块，无公钥证书结构。 | **极大便利**：无需绕过非对称签名即可制作合法映像。 |
| **安全启动 (Secure Boot / eFuse OTP)** | **否** | AC632N 固件头部未置位安全芯片锁，USB 升级工具允许“擦除整个 FLASH”。 | **可重写**：允许全量更新固件并正常启动执行。 |
| **硬件回滚限制 (Anti-Rollback)** | **否** | ISP 模式下无防降级版本号比对硬件拦截。 | **安全**：可自由刷写任意版本固件。 |
