# 芯片内部 ROM 与 Bootloader 深度逆向及救砖恢复能力报告

## 一、概述与关键架构层级划分

在嵌入式逆向工程与救砖分析中，必须严格区分四种不同层级的代码实体，不可混为一谈：

```text
┌─────────────────────────────────────────────────────────────┐
│ 0. 芯片内部 Mask ROM (硬件制造固化在硅片内部，只读，无法被擦除或损坏)│
└──────────────────────────────┬──────────────────────────────┘
                               │ (引导/应急下载)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. 内存注入 Loader (PC端推送至芯片 SRAM 执行的临时驱动程序)   │
└──────────────────────────────┬──────────────────────────────┘
                               │ (烧录/擦除/校验)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. Flash 二级引导器 (存放于外挂 SPI Flash 0x0000A0 的 uboot)   │
└──────────────────────────────┬──────────────────────────────┘
                               │ (系统初始化与应用跳转)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 主应用程序 (存放于 SPI Flash 0x002120 的 app.bin)         │
└─────────────────────────────────────────────────────────────┘
```

## 二、芯片内部 Mask ROM 机制逆向

### 2.1 物理属性与不可损毁性 [E2][E3]
- **芯片型号**: 杰理科技 AC632N / BD19 系列
- **ROM 虚拟地址空间**: `0x02100000 - 0x02120000` (或 `0x1E000000` 引导入口)
- **物理介质**: 硅晶圆光刻掩膜 ROM (Mask ROM)
- **技术特性**: 
  - 没有任何写操作或擦除操作可以改变 Mask ROM 中的数据。
  - 即使 SPI NOR Flash 被物理全片擦除（全 `0xFF`）或写入完全错误的乱码固件，**Mask ROM 始终完整无损，永远可用**。

### 2.2 启动仲裁与进入 ROM 下载模式的机制 [E2][E3]
芯片上电冷启动时的硬件时序：
1. **Flash 完整性自检**:
   - Mask ROM 首先通过硬件 SPI 控制器读取板载 Flash 物理地址 `0x000000` 处的 32 字节 Flash Header。
   - 校验 Magic (`Xn1\x07`) 与 CRC16（原厂固件为 `0x51D8`）。
   - 若 Header 正确且 CRC 匹配，进一步读取 `0x0000A0` 处的 `uboot.boot` 并校验其头部，然后跳转执行 `uboot.boot`。
2. **应急回退（Mask ROM USB 模式）**:
   - 若 Flash 为空片（全 `0xFF`）、Header 校验失败、或 Flash 无法正常读取数据：
   - **Mask ROM 判定为非法固件，立即终止 Flash 引导流程，自动激活内置 USB 协议栈，进入芯片硬件 ROM 下载模式**！
   - 在此模式下，SoC 在 USB 总线上枚举为专有下载设备：
     - **VID**: `0x4A4C` (`JL` - 杰理科技厂商 ID)
     - **PID**: `0x3412` (Mask ROM 通信接口) 或 `0x0200` (通用下载器)
3. **硬件强制使能手段（短接救砖）**:
   - 如果用户写入了能够通过 Header 校验但内部死循环的“假固件”，Mask ROM 可能会卡死在 Flash 代码中。
   - 此时，只需在手柄上电插入 USB 的瞬间，**短暂将 SPI Flash 的片选引脚（CS/PIN 1）或数据输出引脚（DO/MISO）对地（GND）短接 0.5 秒**。
   - 硬件强行使 SPI 读取返回 `0x00` 或 `0xFF`，Mask ROM 判定校验失败，即可**百分之百强制唤醒内部 ROM 下载模式**！

## 三、内存注入 Loader (`loader.bin`) 运行分析

在 `updater_unpacked.exe` 中提取到的 Loader (`loader.bin`) 是实现救砖的关键环节：

### 3.1 Loader 注入流程 [E2]
1. PC 升级器检测到处于 Mask ROM 状态的手柄。
2. 调用 `jl_usb_scsi_common::writeRam` 命令（通过 SCSI 专有 CDB `0xFD` / `0xFB`），将位于 PC 端内存中的 `loader.bin` 逐包分块写入芯片内部 SRAM（地址 `0x00000000`）。
3. 调用 `jl_usb_scsi_common::cpuRunAddr(0x00000000)`，命令主控 CPU PC 寄存器跳转至 SRAM 执行。
4. 主控从 Mask ROM 切换至 SRAM Loader 接管。

### 3.2 Loader 内部驱动能力 [E2]
Loader 包含一套完整的 SPI NOR Flash 底层驱动程序，直接绕过损坏的 Flash 代码：
- **时钟自适应**: 自动探测 Flash 的最大读写频率与工作电压（支持 1-Line, 2-Line, 4-Line 模式）。
- **扇区解锁与写使能**: 自动发送 SPI NOR `0x06` (WREN) 和 `0x01` (WRSR) 清除任何写保护位。
- **全物理空间编址**: 支持从物理地址 `0x000000` 到 `0x07FFFF` 的任意扇区擦除 (`0x20`) 与页编程 (`0x02`)。

## 四、正常升级模式与 ROM 下载模式对比矩阵

| 特性维度 | 正常固件升级模式 (Normal DFU) | 芯片 ROM 下载模式 (Mask ROM ISP) |
| :--- | :--- | :--- |
| **触发方式** | 手柄开机，插入 USB，按住 `配对 + B` 键 2 秒 | Flash 为空、Bootloader 损坏、或硬件短接 Flash 引脚 |
| **指示灯状态** | 指示灯熄灭 (被正常固件关断) | 指示灯完全不亮 (未被软件点亮) |
| **USB 枚举身份** | USB Mass Storage (SCSI 厂商扩展设备) | JieLi USB Update Device (`VID 0x4A4C, PID 0x3412/0x0200`) |
| **依赖代码** | 依赖 Flash 中的 `uboot.boot` 或 `app.bin` 响应按键 | **完全不依赖 Flash 中的任何代码**，由硅片只读硬件维持 |
| **PC工具状态** | 升级工具状态栏显示 `ONLINE` (绿色) | 升级工具同样支持检测并显示 `ONLINE` / `Device Connected` |
| **擦除/恢复能力** | 可刷写完整固件 (包含 uboot.boot) | 可将全空片或损坏 Flash 从 0x0 完整恢复 |
| **变砖致死风险** | 固件写坏后无法通过按键进入此模式 | **终极兜底保障**，任何软变砖均可通过此模式救回 |

## 五、恢复能力评估结论

1. **设备绝不可能发生永久性“不可逆硬变砖”**:
   - 因为 JieLi AC632N 拥有硬件硬化的 Mask ROM，刷写过程即使出现固件错误、校验失败或半途断电，均无法破坏 Mask ROM。
2. **官方升级工具与原厂 UFW 已具备完整救砖要素**:
   - `L1161 固件升级程序_1.4.40.exe` 内置了完整的 `loader.bin`，并内置了针对 Mask ROM 的 `writeRam` 和 `runLoader` 通信协议。
   - 原厂固件包 `L1161 L1162 IINE-reader.ufw` 包含自地址 `0x000000` 开始的完整 212 KB 基础系统（包括 `uboot.boot` 二进制）。
   - **因此，只要设备进入 Mask ROM 模式，官方工具即可直接执行全盘烧录完成救砖，无需第三方编程器**！
